# 运河多式联运履约

用**真实履约**回答平陆运河新路线是否更快、更省——而不是只看 750km 对 990km 的理论航程。

六堡茶出口经理看到航程缩短，仍不能直接承诺更早交货：**船闸窗口、港口作业、箱位/集装箱、报关截关、越南收货预约**中任何一环节都可能抵消航程优势。本系统把这些环节建成带容量与班期的可占用资源，按合同逐段排程、执行，并在延误、甩箱、改港、退关、客户改量时**只重排尚未执行的部分**，原承诺整版保留、释放出的资源不被重复占用。

## 能回答什么

- **更快吗**：以同备货日旧线（西江—南沙—海防—河内，990km）为基准，运河（750km）和海铁（860km）的墙钟交付时间对比——含每一处班期/截关/船闸/预约等待。
- **更省吗**：按锁定的报价版本（通航促销 v1 / 标准 v2 / 旧线 v3 / 海铁 v1）逐航段计费；最终结算把成本差异归因到具体航段与异常附加费，并与旧线全程对账。
- **异常后还成立吗**：在途船闸延误、钦州甩箱、海防拥堵改海铁、退关重报、客户改量，只动未执行尾部；货主得到唯一一致的到达与费用变化，调度员可比较旧线与替代方案。

示例数据会自然涌现一个关键现象：运河船闸端只延误 5.7 小时，却因错过钦州—海防支线班期，把交付级联推迟 4 天——理论航程优势被一个接驳环节吃掉，且费用不变。

## 运行

```bash
python -m src.demo          # 端到端演示：比选→建单→异常→交付→结算，导出 out/fulfillment_state.json
python -m unittest discover -s tests -v   # 38 项测试（资源/排程/异常/追溯/结算/契约）
```

无需第三方依赖，标准库即可（Python ≥ 3.11）。

## 覆盖的业务对象

- **合同与历次报价** `fixtures/contracts.json`、`fixtures/rates.json`：六堡茶（分两批 3+3TEU，各自交付窗口）、汽车散件（24TEU）；五张历史报价、四张费率卡、八项异常附加费标准。
- **路线航段** `fixtures/network.json`：运河线（含马道/企石/青年三道船闸检查点）、旧线、海铁线；节点、里程、参与方。
- **箱位与运力**：直达班轮、近海支线、公路班车、国内段/越段班列，按班次限 TEU。
- **船闸计划**：三道闸每日固定窗口、单窗容量、过闸耗时。
- **港口作业**：梧州/钦州/南沙/海防/港东/凭祥，按自然日作业能力与作业时长。
- **海铁衔接**：钦州港—港东短驳、港东装车、凭祥换装、两国铁路接驳。
- **跨境单证**：出口报关、转关放行、越南进口清关、友谊关跨境申报，各自截单/放行时间与必需单证（RCEP 原产地、植检、提单、舱单等）。
- **目的地预约**：河内茶品/汽车两套收货窗口与每日名额。
- **集装箱供给**：梧州/钦州按周的空箱可供量。

## 模块结构

| 文件 | 职责 |
|---|---|
| `src/timeutil.py` | 朴素当地时间、班期/窗口选择 |
| `src/catalog.py` | 网络/费率/合同资料的读取与索引 |
| `src/calendar.py` | 资源占用日历：六类时间桶容量、原子批量预留、释放防重、核销、重排 `swap` |
| `src/model.py` | 合同、分段、计划版本、航段、费用行、单证、交接、异常 |
| `src/planner.py` | 链式排程（班期/船闸/截关/作业/预约）、在途船闸原子改订、dry-run 比选 |
| `src/service.py` | 建单、执行交单、五类异常重排、承诺版本化、货主一致视图 |
| `src/settlement.py` | 逐航段成本归因、交接台账、单证齐套、承诺时间线、旧线基准 |
| `src/report.py` | 文本报告渲染 |
| `src/contract_check.py` | 零依赖 JSON Schema 校验器 |
| `src/demo.py` | 端到端情节与状态导出 |

## 关键设计约束（均有测试守护）

- **只重排未执行部分**：已执行航段冻结深拷贝；在途航段（班次箱位、已过船闸）整体冻结，仅原子改订未过船闸窗口；退关从被撤的报关步重做。
- **原承诺可追溯**：每次异常产生新版本（`ACTIVE`/`SUPERSEDED`），v1 的到达、费用、逐航段计划永不被原地改写；在途改订前对旧航段留存快照。
- **资源不重复占用**：预留按批原子（任一桶超容则整批不落库）；重排用 `swap`（先按剔除待释放口径校验，再同时释放旧占用、落新占用）；已执行占用**核销**（仍计容量但不可再释放/改订）；重复释放直接报错。
- **一致的货主视图**：到达与费用变化统一从当前版本读取，差异逐条归因到异常单与版本号。
- **结算说明来源**：基础费逐段差（报价版本/改量/改线段）＋异常附加费（甩箱改配、超免堆堆存、退关重报、单证重制、改线操作），并校验对账平衡；逐次货权/责任交接标注完成/待交接/撤销，单证列出缺交项。

## 契约

- `contracts/domain.schema.json`：共享领域资料（原有）。
- `contracts/fulfillment.state.schema.json`：履约状态导出结构（版本化承诺、航段、占用、费用、异常）。`tests/test_contract.py` 用真实演示产出校验该契约。

仓库不保存账号、密钥、连接串或真实身份信息；时间均为业务当地时间，无时区换算。
