# 运河多式联运履约

用真实履约数据回答六堡茶出口经理的问题：**平陆运河把航程从 990 公里缩短到 750 公里之后，交货到底能不能更早、费用到底省不省？** 航程优势必须依次通过船闸排档、港口泊位、船期箱位、报关窗口和越南收货预约，任何一环都可能抵消理论收益，因此系统以资源容量和逐段交接为约束做排程、履约与结算。

## 覆盖范围

| 环节 | 实现 |
| --- | --- |
| 合同 | `fixtures/network.json` 中的合同（货量、收货窗、贸易术语、选用报价） |
| 历次报价 | 旧线 2 版、运河线 3 版（通航前预估→首月价→协议价）、海铁/盖邻各 1 版；分段单价合计=总价 |
| 路线航段 | 旧线 R-OLD(990km)、运河线 R-CANAL(750km)、海铁线 R-RAIL(780km)、改港盖邻线 R-CAILAN(680km) |
| 船舶箱位 | 班轮/班列航次箱位池，含截关时间与背景货量占舱 |
| 船闸计划 | 马道/青年/企石三级船闸按日时间窗与通过偏移联动排档 |
| 港口作业 | 始发港换装、目的港靠泊独立航段与泊位窗 |
| 海铁衔接 | 梧州-南宁-防城班列、南宁南场站换装窗 |
| 跨境单证 | 出口报关（可退关撤放行/改配重报）、海防/盖邻进口清关、提单/运单交接 |
| 目的地预约 | 河内收货预约窗容量，甩箱/改港时取消释放 |

## 核心规则

1. **同一票货允许分段完成**：订舱可拆成多个批次（`Split`），各批独立排程、独立交付。
2. **只重排尚未执行的部分**：已发运/已到达/已交接的航段冻结；延误、甩箱、退关、改港、改量都从断点向后重排，已发生费用沉没留痕。
3. **释放资源不得重复占用**：容量台账保证不超订；重排先影子验证可行，再"先释放旧占用、后占用新资源"；同一占用释放两次直接报错；释放出的舱位可立即被其他客户买走。
4. **原承诺可追溯**：每次下达/重排生成不可变的承诺快照（ETA+逐段费用+时刻），旧版本永久保留并标记被取代。
5. **货主一致口径**：分批的 ETA 变化、费用变化、收货窗符合性逐批展示，互不串扰。
6. **调度员可比选**：订舱时留存各替代路线的影子基线；异常断点上可再做尾部影子比较（可叠加封港黑名单），不占资源、不改承诺。
7. **结算可归因**：逐段列示计划版本、状态、准点情况、相对原承诺的费用差异；附加费（甩箱堆存、退关手续费）、迟交违约金单列；每次交接的对手方、时刻、单证齐备情况逐项核对；并与旧线无异常反事实逐批对照。

## 模块

- `src/models.py` — 领域模型（合同/路线/报价/船期/窗口/批次/航段/占用/承诺快照/报关单/预约/事件）
- `src/resources.py` — 资源容量台账（超订拒绝、单次释放、自检）
- `src/network.py` — 网络资料装载与一致性校验（报价合计、资源引用、背景货量）
- `src/planning.py` — 前向排程器（截关、船闸通过时刻、窗口容量；影子/提交两模式）
- `src/service.py` — 履约编排（订舱分批、发运/到达/交接、延误/甩箱/退关/改港/海铁切换/改量）
- `src/settlement.py` — 最终结算、逐段归因、交接清单、单证状态
- `src/reporting.py` — 货主视图与调度员视图
- `fixtures/network.json` — 网络与商业数据（不含账号、密钥、真实个人信息）
- `contracts/network.schema.json` — 网络资料结构契约

## 运行

```bash
python -m unittest discover -s tests   # 全部测试
python examples/demo.py                # 六堡茶 5 TEU 全异常剧本
```

演示剧本：09-27 订舱分 2/2/1 三批 → S2 航道管制延误 30 小时 → S1 客户减量 2→1（舱位释放即被外部买走）→ 台风封港，S3 已放行未出境、退关后改港盖邻 → S2 在 1006 航次被甩箱改配 1013 → 全部交付后结算，逐段说明费用差异与每次交接是否完成。
